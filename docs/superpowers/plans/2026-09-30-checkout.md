# Checkout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the five-step local checkout, persistent fictitious orders, and durable confirmation page without storing payment-card data.

**Architecture:** Define the shared order domain first, then add pure checkout validation/calculation functions and a sanitized Zustand order store. Build a single React Hook Form flow split into focused step components; final submission snapshots the cart, stores the order, clears the cart, and navigates to confirmation.

**Tech Stack:** React, TypeScript, React Router, React Hook Form, Zod, Zustand persist, CSS Modules, Vitest, Testing Library

**Spec:** `docs/superpowers/specs/2026-09-29-checkout-design.md`

## Global Constraints

- No backend and no real payment.
- Accept only demo card `4242 4242 4242 4242`, expiry `12/30`, and CVC `123` when payment method is `card`.
- Never persist checkout drafts or card fields.
- Persist final orders under `marche-frais-orders-v1` only.
- Store prices as integer cents and recalculate totals from cart items.
- Do not push to GitHub.

## Review Focus

- Corrupt or obsolete order data in `localStorage` must be ignored without breaking hydration.
- A cart that becomes empty before final submission must not create an empty order.
- Repeated final submission must create at most one order and clear the cart once.
- Card validation must be conditional: PayPal must not require card fields, while a card order must reject any non-demo credentials.
- Refreshing checkout must reset form progress while refreshing confirmation must recover the stored order.
